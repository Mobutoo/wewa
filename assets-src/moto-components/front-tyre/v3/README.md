# Front tyre v3 — local G3 repair, diagnostic only

Same physical component `MOTO-TYRE-FRONT-001`; the historical v1 sources and v2 material-transfer study are unchanged. This directory currently contains an editable **diagnostic**, not a production candidate received for appearance or fit.

`build.py --diagnostic-save-after=4` must be passed after Blender’s `--` separator. It reads the exact legacy inspection mesh, retains every original vertex, changes only existing groove-field overlap vertices radially, and inserts shared edge vertices with per-corner seam-preserving UV interpolation. The old unmodified vertex positions, all old X coordinates and actual six bounds remain exact. The working diameters and tread definitions are estimates; this recipe does not identify the OEM mould.

The saved diagnostic is `front-tyre-v3-junction-diagnostic-v1.blend` with collection `WEWA_FRONT_TYRE_V3_LOCAL_JUNCTION_CORRECTION`; its evaluated inspection export has the matching stem. `diagnostic-source-geometry-check.json` in the review directory describes 581140 triangles and explicitly states that the sampled20µm author goal was **not** reached. `check_diagnostic.mjs` reads the actual exported mesh: closure, volume, connectedness, triangle areas, UV and glTF pass. These checks do not receive the surface appearance.

`render_gray_compare.py` produces two native24sample macro images using one fixed camera/light/exposure and one constant gray material. It does not save either source. The baseline keeps its old normals; the new mesh uses its actual refined smooth normals with a C1 taper toward retained old normal inputs. The storage quantization of custom normals is measured; bit-identical outside stored normals are not claimed.

The before-work plan and additive iteration history are in `creative/research/front-tyre-junctions-v3/`. Failed recipes/logs and the exact current diagnostic author inputs are preserved privately under `/workspace/wewa-assets/work-in-progress/front-tyre-v3/`. No photograph pixels are used as textures. There is currently **no new material bake, final96 series, runtime reception, LOD or iPhone performance claim** for v3.
